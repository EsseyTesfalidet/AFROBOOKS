# Installed reader appearance

The installed app uses a book-inspired presentation in `components/reader/reader-mobile.css`. Warm Paper and Sepia, and the existing Dark/Night themes, keep their own palettes. A light edge shadow, centered chapter openings, a small ornament, a quiet running title and a compact folio add depth without raster textures or processing the manuscript. Paragraph alignment, Unicode content, text selection and reflow remain intact. Ordinary browser sessions retain the previous reader presentation.

Tapping the reading area hides both toolbars. Focus mode keeps the same page geometry and reading anchor; it does not resize the columns or change the number of pages. Hidden controls become inert and leave the accessibility tree. A small footer button, another tap, or Escape restores the controls. Selecting text and following links do not trigger focus mode. Save failures keep the visible controls and retry message available.

The compact footer cycles through page/chapter number, percentage and estimated time remaining. Page numbers refer to the current reflowed chapter, not printed page numbers. Existing position saving and ownership/preview checks are unchanged. The display preference is stored locally with reader settings. Estimated time uses the existing word-count heuristic and is not a precise timing prediction across languages.

The appearance sheet adds an actual chapter-text preview and Comfortable/Large text presets. The preview is plain text extracted from the already sanitized, accessible chapter; it never fetches additional chapters. Presets adjust font size, spacing and margins together, without resetting the page color, font family, reading mode or author text flow. Previously saved themes and reading preferences remain supported.

`useReaderPageMotion` adds a 460 ms 3D paper flip when a swipe finishes or a page button/key is used. A temporary DOM copy shows the outgoing page lifting off on forward turns; backward turns bring the previous page back over the outgoing one. Perspective, a shaded reverse face, edge highlights and a cast shadow give the sheet depth. It is a swipe-triggered page flip, not a finger-tracked corner curl.

Only the decorative copy rotates. The actual text and reader viewport keep their normal geometry, so selection, reflow and position saving stay accurate. The copy preserves the current column offset, styles and Unicode text, uses only already-authorized chapter content, is inert/hidden from assistive technology, and has IDs, links and live-region attributes removed. It is removed when the turn finishes. No canvas, external renderer, new dependency or additional chapter request is used.

Navigation succeeds immediately. Rapid turns replace the previous sheet; rotation, appearance changes, opening a panel, selecting text, hiding the app and unmounting cancel it. Scroll mode, ordinary browser mode, the user's animation toggle and reduced motion disable the effect. Unsupported animation APIs or chapters exceeding the temporary-copy budget (2,000 DOM nodes or 200,000 text code units) fall back to an immediate page change rather than duplicating an oversized manuscript on a phone.

Verification: `tests/mobile-reader.browser.cjs` exercises the real reader, session, pagination and preference code with simulated data boundaries. It checks forward/backward 3D flips, inert copies without duplicate IDs, sheet cleanup, rapid turns, chapter boundaries, rotation cancellation, oversized-chapter and unavailable-API fallbacks, focus without repagination, swipes, selection, animation enabled/disabled/reduced-motion behavior, preview/presets, saved position, 320px portrait and phone landscape layouts, large text and unchanged English/Tigrinya/Arabic/Chinese text on the turning sheet, free-preview isolation and the unchanged website. It uses Chromium with installed iOS mode simulated; this does not replace physical-device checks. Run with `PLAYWRIGHT_PATH`, optional `EDGE_PATH` and optional `SCREENSHOT_DIR`. The reader unit tests, ESLint and the production build are also checked; the existing mobile appearance browser checks passed for the preceding appearance update.
